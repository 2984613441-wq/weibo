# ADR 0002 — 多 AI 协作协议（DSH / Gemini / Claude / Codex）

- 日期：2026-11-21
- 状态：已接受
- 提出：lead (DSH)
- 决策人：29845（用户）

## 背景

用户明确：后面会有 Gemini、Claude、Codex 一起参与学习。四个 AI 共享同一个文件系统，但**各自上下文不互通**。

已有失败模式（来自用户过往笔记）：四份 md 互相打架，没人知道哪份是最新。

## 决策

### 1. 单一真相文件，按"责任"分区，不按"事件"分区

| 文件 | 写什么 | 谁能写 |
|---|---|---|
| `STATUS.md` | **只有当前状态**：现在在哪、下一步 | 任何 AI，但每次只覆盖"现在"，不追加历史 |
| `HANDOFF.md` | **只有交接**：谁做的、停在哪、置信度 | 每次收工的 AI 覆盖写 |
| `CHANGELOG.md` | **只追加**：哪天交付了什么 | 任何 AI，只能追加到末尾 |
| `docs/adr/*.md` | **只追加**：为什么这么定 | 提出决策的 AI，新建文件，不改旧的 |
| `notes/*.md` | 学习笔记，一案例一篇 | 学习的人；同名文件不覆盖，加日期后缀 |

**规则：同一件事只写在上述一个地方。** 状态不写进 CHANGELOG，理由不写进 STATUS。

### 2. 文件所有权（避免并发覆盖）

同一时刻，一个文件只有一个写者：

- 开始写 `STATUS.md` / `HANDOFF.md` 前，先读它，看 `updated` 是不是自己上次写的
- 不是自己写的 → 说明别人改过，先读 `CHANGELOG.md` 补上下文，再改
- 两份笔记同主题冲突 → **不合并**，各留一句"分歧声明"（依据 + 替代方案），交用户裁决

### 3. 最新优先，且必须带日期

任何结论引用前先看日期。旧结论与新结论冲突时，以新的为准，旧的在原地标注 `⚠️ 已被 YYYY-MM-DD 版本取代`，**不删除**。

### 4. 交接格式（固定五段）

```markdown
commit:  无 git / 或 hash
updated: YYYY-MM-DD HH:mm (Asia/Shanghai)
status:  当前阶段一句话
next:    下一个动作，具体到"打开哪个文件做什么"
置信度:  关键事项 0.x + 依据
```

### 5. 各 AI 的角色分工（建议，非强制）

| AI | 强项 | 建议主责 |
|---|---|---|
| DSH | 文件系统实证、批量盘点、脚本执行 | 事实核验、目录治理、批量提取 |
| Claude | 边界与合规审查、反例 | 审查结论是否越界、是否有后门式假设 |
| Codex | 工程落地、可执行验证 | 批处理脚本、参数化扫描、自动化 |
| Gemini | 多模态、图文对照 | 从 PDF 图表反推设置、结果图判读 |

分工是**建议**，用户是最终裁决。同一件事原则上只派一个主做，其他做互补视角。

## 替代方案与取舍

| 方案 | 否决原因 |
|---|---|
| 每个 AI 各写一份自己的状态 | 就是当前的病根 |
| 用 git 分支隔离 | 当前无 git；四人抢同一工作树更乱 |
| 单一超大 `NOTES.md` | 并发编辑冲突面最大，且历史不可追溯 |

## 后果

- 新 AI 接入成本 = 读 4 个文件（AGENTS / STATUS / HANDOFF / architecture）
- 冲突从"内容打架"降级为"文件写冲突"，靠 `updated` 时间戳可检出
- 需要所有人遵守同一套格式，首次接入时由用户在提示里指明"先读 AGENTS.md"
